## 何时使用

| 场景 | 是否本地 deploy |
|------|----------------|
| 日常开发 / 常规发布 | **否** — push `relay/dev_*` → Gitea mirror；需要时再手动 FF / CI |
| Gitea 或 GitHub 长时间不可达，业务必须先修线上 | **是** — 本文流程 |
| 仅本机联调 | `wrangler dev`，不必 deploy |

**不要**把本地 `npm run deploy` 当作常规路径（无 GHA 门禁、deploy-tracker 可能无记录、易与 `master` 漂移）。

---

## 步骤

<Steps>
  <Step>
    **确认本机 Cloudflare 凭证**

    `CLOUDFLARE_API_TOKEN` / `wrangler login` 已可用（与生产账号一致）。
  </Step>
  <Step>
    **依赖**

    - 优先：本地已 `npm ci`，SDK 可用 `file:../framework_sdk_worker` 旁路联调。
    - 若 `package.json` 指向 GitHub Packages，需本机 `NODE_AUTH_TOKEN` 或临时改回 `file:`（**勿提交**临时改动，或事后还原）。
  </Step>
  <Step>
    **门禁（本地）**

    ```bash
    cd <worker>
    npm run check && npm test
    ```
  </Step>
  <Step>
    **部署**

    ```bash
    npm run deploy
    # 或 npx wrangler deploy
    ```

    有 D1 的 Worker 另按 CF Builds 模板执行 `wrangler d1 migrations apply … --remote`。
  </Step>
  <Step>
    **冒烟**

    `curl` health / 关键业务路径；需要时 `wrangler tail`。
  </Step>
</Steps>

## 事后对齐（必须）

网络恢复后：

1. 将本次本地部署对应的 commit **推到 Gitea**（`relay/dev_*`）并确认 mirror 到 GitHub。
2. 手动 FF `relay/dev_*` → `dev_*`（或网络好时 `git push github`），跑通 Release PR，使 **GitHub `master` 与线上一致**。
3. 在 deploy-tracker Dashboard 核对是否出现对应 CF Builds / 必要时手工对账。
4. 还原任何临时的 `file:` SDK / 未提交配置。

未做事后对齐会导致：**下次 CF Builds 用旧 `master` 覆盖你本地刚修的线上**。

---

## 与 Gitea 中转的关系

- Gitea **只同步代码**，不替代本应急通道。
- 应急 deploy **不经过** Gitea / GHA；恢复后仍以 GitHub `master` + CF Builds 为权威发布轨。
